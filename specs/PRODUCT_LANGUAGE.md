# 产品表达与术语规范

适用：用户与市场调研、企业访谈及共享工作台。首页品牌文案保持“以访谈，唤出知识与经验。”。

## 导航和工作阶段

| 位置 | 统一表达 |
| --- | --- |
| 创建入口 | 新建研究项目 / 创建研究项目 |
| 首页输入 | 这次想研究什么问题？ |
| 流程画布 | 调研路径 |
| 资料入口 | 研究资料 |
| 助手 | 研究助手 |
| 分析入口 | 用户洞察（市场与用户）/ 研究洞察（企业） |
| 六阶段 | 定义调研目标 → 研究背景与方案 → 访谈提纲 → 开展访谈 → 洞察分析 → 研究成果 |

研究方案包括研究问题、待验证假设、研究对象、招募标准、使用场景与执行安排。洞察分析阶段整理证据、分析原因并形成需求建议；不新增一套阶段编号或改变原有 API 状态机。

## 成果用语

| 术语 | 含义与边界 |
| --- | --- |
| 访谈原话 | 受访者实际陈述，保留原意和来源，不等于已独立核实的事实 |
| 研究发现 | 原始材料中可观察到的行为或现象 |
| 用户 / 业务洞察 | 对行为原因的解释，说明推断依据和局限 |
| 需求机会 | 值得进一步研究的问题或改进空间 |
| 需求建议 | 可能采取的产品行动，说明证据和适用对象 |
| 待验证假设 | 尚缺证据的判断，列出验证方法 |

个体提出某功能只构成一条诉求。需进一步了解使用场景、出现频率、影响程度、现有流程和替代方案；不能直接写成普遍需求。缺少频次、影响或样本证据时不编造量化评分，研究建议不等于批准排期。

## AI 对话

自然承接已有信息，按缺口一次聚焦一个问题，例如：

- 这次研究希望支持哪个产品或业务决策？
- 本次计划访谈哪些目标用户或业务角色？
- 目前有哪些待验证假设？
- 最近一次遇到这个问题时，具体发生了什么？
- 这条判断有哪些访谈原话支持？

计划、分析、报告及用户授权新增的研究文档采用同一套规范。实时追问使用访谈主持人与研究者称谓，保留中立、简短和不诱导的原则。

## 场景与兼容边界

求职面试保留面试目标、简历、模拟练习、作答及复盘；口述史保留讲述、记忆、人生经历与传记，不强行使用需求假设或用户痛点框架。

保留所有场景编号、阶段索引、命令、字段键、历史选项值及引用格式。新增研究目标选项兼容旧选择。已有访谈原话、人工标题、报告正文和旧聊天记录不批量替换；新增成果和新的助手回复使用新规范。

前端共享标签在 `frontend/src/sceneRegistry.ts`，阶段和目标选项在 `backend/research_platform.py`，研究提示规范在 `backend/platform_ai.py`，访谈即时提示在 `backend/kimi.py`，报告边界在 `backend/research_report.py`。
