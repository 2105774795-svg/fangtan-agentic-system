## 1. 产品概述

### 新增范围：时叙录第一版及双入口导航

首页采用上下双入口：上方“汇言笔”进入原工作区，内部保留“实战访谈”和“现场录音”两个标签及原有调研访谈 UI、表单和功能；下方“时叙录”进入私密人物空间。原“人生之书”仅更名为“时叙录”，不修改历史资料正文、归属或隔离规则，不更改 `memoir` 内部接口、数据库表名及文件路径。本轮已经用户确认，测试通过后发布；上线状态以实际发布审计为准。

时叙录保留专属宽屏工作区：桌面采用左侧人物/功能导航、右侧讲述与阅读，手机单列适配，主要正文不小于18px、说明不小于16px、主要按钮不小于44px高。第一版面向经过员工中心单独验证的本人/授权整理者，完成“独立人物档案 → 一问一答录音或文字讲述 → 跨次记忆与待确认线索 → 有原文依据的章节草稿 → 确认及导出”。不在本轮实现家人邀请、照片协作、全双工打断、声音克隆或鸿蒙真机功能。

- 即使原共享工作区关闭内置认证，时叙录仍强制独立登录并按正整数用户 ID 隔离。旧列表、搜索、项目、录音下载及通用任务接口不能读取私密资料。建档前须明确记录讲述者授权及云端处理同意；整理者不能替未同意的人上传材料。
- 原录音与原始转写不可被 AI 改写覆盖；助手问题不算人生事实。跨次提取的事件保留候选/确认状态、约数时间和原文片段，不把不同讲述自动裁定为唯一真相。拒答、暂停和结束不强迫追问。
- 章节读取全部所选人物原始讲述，分块处理、不以各场纪要替代；每个生成段落必须关联真实连续原话。引用校验不等于语义或外部事实核验，需本人/授权整理者审核。来源变化后旧版本不得继续当作当前有效结果确认或导出。
- 半双工录音先停止麦克风再播放问题，避免助手声音混入原稿。首版仅使用设备本地中文音色，无可用音色时明确回退文字，不默认向未知远程 TTS 服务发送内容。页面离开停止采音/播报并清理内存展示，不在浏览器持久存储故事正文。
- 验收必须包括 AUTH=false 下独立登录、双账号越权、旧接口隔离、幂等重试不重复记稿、跨次承接、完整原稿成书、删除后阻止异步回写及原访谈回归；通过后按用户授权部署 API 与 Worker，并核对原有资料不变。

“访谈·体察”是一套面向一线访谈场景的 AI 访谈辅助系统。系统在访前帮助用户生成采访提纲，在访中完成录音、转写、信号识别、覆盖度判断和追问建议，在访后生成可核验的纪要素材包。

产品主路径为：访前准备 → 现场实时录音或导入已有材料 → 生成纪要 → 历史管理。

2026-10-15 架构第一阶段保持现有 UI 和业务入口，将五类耗时任务（提纲/地点背景、纪要、总访谈记录、导入、发言人分离）交给独立后台进程和持久队列。目标是断开请求不丢任务、有限重试与安全恢复，不是更换全部技术栈；本轮本地交付，不自动启停或发布。

后续三项增强继续保持原 UI，仅原卡片补判断证据/地点来源、项目详情补下载按钮：完整逐字稿 AI 问透评估、带来源的联网地点背景、权限内项目资料 ZIP。当前文档记录待验证发布的代码能力，不表示本轮已经上线；发布须以真实验收和部署审计为准。

## 2. 背景与问题

一线访谈尤其是商户调研存在以下常见问题：

- 新手不知道如何开场、如何取得录音授权；
- 采访提纲过于宽泛，问题顺序和对象不匹配；
- 访谈过程中容易漏问经营数据、成本、家庭和预期等重要信息；
- 受访者出现含糊、矛盾、异常数字或情绪变化时，采访者来不及组织追问；
- 访后整理耗时，逐字稿、关键事实和待核实项分散；
- 页面刷新、网络断开或服务重启后，进行中的访谈难以继续；

## 3. 产品目标与非目标

### 3.1 产品目标

1. 降低访前准备成本，根据主题、对象、行业和采访重点生成可编辑提纲。
2. 让采访者专注对话，系统自动完成分片录音、转写和过程记录。
3. 在关键信号出现时给出具体、可直接使用的追问建议。
4. 用七维覆盖模型提醒采访者补齐信息缺口。
5. 允许进行中的访谈安全恢复，避免历史内容覆盖或重复。
6. 访谈结束后生成结构化纪要素材包，并保留人工核验要求。
7. 提供历史会话查看、改名、继续、补生成纪要、下载和删除能力。
8. 支持把既有音频或常见格式文字稿直接转为结构化、可核验的访谈纪要。

### 3.2 当前非目标

- 多租户和复杂角色权限；
- 跨设备云端音频长期归档；
- 专业录音剪辑、说话人分离和人工校对工作台；
- 标签和跨项目自动对比（同一项目内综合记录与资料 ZIP 已纳入范围）；
- 移动端原生 App 和离线转写；
- 将 AI 生成内容视为无需核实的事实或可直接发布稿件；

## 4. 用户与使用场景

### 4.1 用户角色

| 用户 | 核心需求 |
|---|---|
| 财经记者/调研人员 | 快速准备、完整记录、及时深挖、快速整理 |
| 实习生/访谈新手 | 获得开场话术、提纲、追问和覆盖度指导 |
| 项目维护者 | 配置模型服务、查看运行状态和维护本地数据 |

### 4.2 关键场景

| 场景 | 用户行为 | 系统结果 |
|---|---|---|
| 访前准备 | 点击录音键后填写主题、对象、行业、地区和重点 | 先生成地点背景，再生成 6～12 个可编辑问题 |
| 现场采访 | 开启麦克风并持续对话 | 每 10 秒分片上传、转写并实时展示 |
| 发现线索 | 受访者表达含糊、矛盾或出现关键数字 | 推送追问建议、理由和备选问法 |
| 查漏补缺 | 查看摸排进度 | 展示七维覆盖率和缺口问题 |
| 中途离开 | 返回开场页或关闭页面 | 会话保持进行中，可从历史记录恢复 |
| 访后整理 | 点击结束访谈 | 等待剩余转写完成并生成 Markdown 纪要 |
| 整理既有材料 | 上传录音或文字稿 | 自动提取内容并生成 Markdown 纪要 |
| 历史管理 | 查看、改名、继续或删除会话 | 数据状态同步更新 |

## 6. 功能需求

### FR-01 开场设置（P0）

- 认证模式下当前员工姓名由登录账号提供，用于内部使用量统计；免登录模式显示“本地使用者”，不发送员工统计。
- 访谈主题可不填，空值使用“未命名访谈”；建议用户主动填写以提高提纲和报告质量。
- 访谈对象支持：商户、企业家、企业高管、一线员工、行业专家、投资人、政府/协会人士、消费者。
- 行业支持：综合/不限、金融业、汽车业、制造业、食品饮料、消费零售、互联网科技、房地产建筑、能源化工、医药健康、农业、交通物流、文化传媒、教育服务。
- 采访重点可选，最多 500 个字符。
- 采访提纲允许手动输入，一行一个问题。
- 现场录音首页不展开设置表单，点击主录音键后再设置地区、采访提纲和勾选问题。地区仅含城市与市场/园区，不提供区县、街道/乡镇/村或具体地址输入；历史地区信息保留。

验收标准：必填项缺失时明确提示；非法对象或行业不得创建会话；最终设置随会话持久化。

### FR-02 AI 采访提纲（P0）

- 用户填写主题及城市、市场/园区后可请求 AI 生成提纲。
- 先联网查询城市与具体市场/园区，以真实搜索来源摘录介绍地点特点，再根据主题、对象、行业、地区和重点生成 6～12 个问题。
- 背景附真实来源链接、标题、原文引用及检索时间，可用时标发布日期。旧文章不代表当前现况；同名异地、无源或失败明确说明，仍可生成提纲，不用模型记忆冒充检索。联网可回查不等于独立事实核验，不编造当地规模、排名、政策或经营数据；搜索不发送主题、重点、逐字稿或个人信息。
- 问题应由浅入深、避免重复，并符合受访对象的认知边界。
- 生成结果回填文本框，用户可继续增删改。
- 再次生成会覆盖现有提纲，必须二次确认。
- AI 生成失败时不阻止用户手动填写并开始访谈。

### FR-03 创建与恢复会话（P0）

- 点击“现场录音”只进入简洁录音首页，不提前创建空会话或申请麦克风。
- 点击主录音键进入准备页，点击“开始录音 · 已选 X 道问题”或“直接开始录音”后创建会话并请求麦克风；从“实战访谈”点击“带筛选提纲进入录音”则只进入工作台，再点“录”采音。同页折叠区的“继续最近访谈”恢复进行中会话。
- 不再保留重复的“继续最近一场未结束的访谈”入口；无可续访记录时进入准备流程。
- 新会话保存使用人、主题、对象、行业、重点和最终提纲。
- 创建后生成一张开场话术卡，包含开场参考和录音授权提示。
- 最近会话 ID 可保存于浏览器，但数据库是最终事实来源。
- 进行中会话可从“继续最近访谈”、历史列表或详情页恢复。
- 恢复时还原逐字稿、提纲勾选状态、建议和七维覆盖度。

### FR-04 现场录音与实时转写（P0）

- 用户首次录音时由浏览器请求麦克风权限。
- 录音默认每 10 秒形成一个 WebM 分片并上传。
- 服务端将音频转换为 16 kHz 单声道 WAV，再调用 DashScope ASR。
- 本地地址使用 Base64 同步转写；配置公网 HTTPS 地址后可使用文件转写方式。
- 单个分片默认最大 20 MB。
- 上传失败自动重试，连续失败的分片在结束访谈前再次尝试。
- 页面实时显示计时、录音状态、上传/转写状态和逐字稿。
- 停止录音只暂停采集，不结束会话。

### FR-04A 导入已有材料（P0）

- “现场录音”保留实时录音与导入材料能力；导入入口收纳于同页折叠区，不与主录音键并列占据首屏。
- 音频支持 MP3、M4A、WAV、AAC、OGG、FLAC、WMA、WEBM、MP4，默认最大 200MB。
- 文字稿支持 TXT、MD、DOCX、SRT、VTT、CSV、JSON、HTML，默认最大 20MB；解析后的有效正文不超过 50 万字符和 1 万段。
- 音频先由 FFmpeg 标准化并按 4 分钟切片，再逐段调用 ASR；SRT/VTT 保留时间，CSV/JSON 尽量保留发言人和时间，普通文本按段落拆分。
- 页面显示接收、解析/转写、归档和纪要生成进度；失败时明确显示原因。
- 成功后创建已完成会话并进入纪要页，逐字稿和纪要进入历史会话；处理中间切片及时删除，音频原件保留供回听，文字稿原件不保留。
- 纪要至少包含：基本信息、一句话结论、内容摘要、关键结论、行动项与待办、主题章节、关键原话、事实数据、分歧/风险/回避点、待核实事项和后续追问。
- 长稿先分段提取事实再汇总；所有结论、原话和待办保留时间戳或段落来源标记，不得编造缺失负责人或期限。

### FR-05 信号识别与追问建议（P0）

- 系统检测受访者表达中的数字、模糊表述、因果、转折、情绪、矛盾等追问信号。
- 命中信号后，可由 AI 结合最近对话、剩余提纲、行业和采访重点生成追问建议。
- 建议包含主要问法，可选包含推荐理由和备选问法。
- 两次 AI 追问建议之间遵循默认 45 秒冷却时间，防止频繁打断。
- 用户可将建议标记为“已问”或“忽略”。
- 建议生成失败不得中断录音和转写。

### FR-06 七维摸排进度（P0）

当前七维模型以商户调研为主要适配对象：

1. 经营者画像；
2. 经营现状；
3. 成本结构；
4. 竞争与位置；
5. 政策与环境；
6. 家庭与个人；
7. 变化与预期。

- 系统依据完整逐字稿作 AI 充分度分析；长稿分块、逐题分批并增量复用稳定片段，不仅靠关键词或手工标记。
- 四种状态为尚未讨论、仅被提到、仍需追问、已有充分回答；非空判断必须附可定位原话证据。充分比例只计算 AI 判为充分的项目；人工已问独立保存，不增加问透比例。
- 原卡片可查看判断依据、证据和下一句追问，并保留手工“问过”标记；已问不等于已充分回答。分析排队、失败或结果滞后显式显示。
- 至少产生 3 句转写后，系统可针对缺口推送提醒；同一会话最多每 5 分钟推送一次。
- 旧资料不因升级、打开列表或只读访问而批量自动发送云端；可明确发起重新分析。AI 问透率是辅助判断，不代表事实质量或采访完成度的最终结论。

### FR-07 提纲进度与实时连接（P0）

- 现场页显示全部采访提纲。
- 用户点击提纲项可查看 AI 原话依据与追问、另行标记已问并持久保存；人工已问与 AI 问透状态相互独立。
- 服务端通过 SSE 推送转写、信号、建议、覆盖度、自动命名和报告事件。
- SSE 断线时页面提示正在重连；重连后通过状态接口校准。
- 前端按转写序号和建议 ID 去重，避免历史回放重复展示。

### FR-08 自动命名和手动改名（P1）

- 未填写主题的会话累计达到 5 条转写后触发一次异步自动命名。
- 结束访谈时仍未命名成功，可再触发一次；总尝试次数最多两次。
- 自动标题不超过 15 个汉字，避免空泛名称和敏感信息。
- 用户可在详情页手动修改为 1～80 个字符的标题。
- 用户命名拥有最高优先级，自动任务不得覆盖。

### FR-09 结束访谈与纪要素材包（P0）

- 结束前停止录音并等待待上传、待转写分片处理完毕。
- 存在失败分片时再次重试；仍失败则提示用户，不直接结束。
- AI 根据主题、对象、行业、采访重点和完整逐字稿生成 Markdown 纪要素材包。
- 报告生成成功后会话状态变为 `done`，不可继续录音。
- 报告结果可在页面阅读，并可下载 Markdown 文件。
- 重复结束或补生成请求应复用已有报告，避免重复生成。
- 页面必须提示用户：AI 整理内容和金句应逐条核实后使用。

### FR-10 历史会话管理（P0/P1）

- 历史列表展示标题、会话状态、对象、行业、转写数量、纪要状态和创建时间。
- 进行中会话优先显示，其余按创建时间倒序。
- 详情页展示访谈重点、逐字稿、覆盖度和纪要状态。
- 进行中会话支持继续访谈；已结束且无纪要的会话支持补生成。
- 已生成纪要支持查看、切换逐字稿和下载。
- 支持手动改名。
- 支持删除，进行中会话删除时明确提示不可恢复。
- 删除操作同时清理关联数据库记录、上传目录、报告文件和留存录音；文件清理失败必须记录。

### FR-11 内部运行数据（P2）

- 认证模式下使用人姓名取自已验证的员工账号，并用于内部使用量统计；不得接受客户端自行指定其他员工姓名。
- 认证模式下纪要生成成功后可向配置的内部统计地址发送使用事件；免登录模式不发送。
- 开发进度接口必须使用 Bearer Token，未配置或令牌错误时返回未授权。
- 用户业务界面不得暴露 API Key、进度令牌或服务端路径。

## 7. 状态与业务规则

### 7.1 实战会话状态

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| `live` | 进行中 | 录音、继续、查看、改名、结束、删除 |
| `done` | 已结束 | 查看、改名、生成/下载纪要、删除 |
| `deleting` | 正在清理 | 不允许继续业务操作 |

### 7.2 报告状态

| 状态 | 含义 |
|---|---|
| `none` | 尚未生成 |
| `generating` | 正在生成 |
| `ready` | 已生成 |
| `failed` | 最近一次生成失败，可重试 |

### 7.3 数据顺序与幂等

- 转写 `seq` 在单个会话内从 0 递增，数据库 `MAX(seq)` 是最终事实来源。
- 页面恢复和 SSE 回放不得重复渲染同一 `seq` 或建议 ID。
- 自动命名、报告生成和删除操作必须避免并发覆盖或重复执行。

## 8. 数据与隐私要求

- 认证模式通过会议龙虾所用员工中心登录。访谈默认仅创建人可见，创建人可指定在职员工只读共享；所有录音、逐字稿、纪要、问答与待办接口均须检查权限。
- 本机单人工作区可显式设置 `FANGTAN_AUTH_ENABLED=false`，打开网页即可使用；所有可访问服务的人都可查看、编辑当前数据目录的现有记录。账户、员工列表、团队共享和分享链接功能暂停（接口返回 `409`，旧链接也不可访问），前端隐藏对应入口，不发送员工统计。
- 免登录不迁移或覆盖历史员工归属；新增记录使用 `owner_id=-1`。切回默认的 `true` 后恢复员工认证，本地新增记录不会自动归属员工或共享，须先导出或另行明确归属。免登录服务应绑定 `127.0.0.1`；AI 密钥、云端发言人分离的公网 HTTPS 回调和单独同意要求仍适用。
- 现场录音和导入音频的原件应保留到会话删除，以支持权限内回听和下载；删除时连同共享、待办、问答记录清理。
- 历史管理应支持关键词搜索、项目分组、待办汇总与统计，详情支持发言人标记、逐字稿问答和纪要人工修订。
- 现场录音下设项目文件夹：支持新建、改名、空项目留存、录音结束后归档及历史记录调整归属；旧名称标签无损迁移，同名项目按创建人隔离。
- 提纲生成前约束城市与市场/园区，不再收集区县、街道/乡镇/村和具体地址。先展示附真实来源及检索时间的联网参考背景，再展示问题；失败/同名歧义明确说明，不影响生成提纲。服务器后台任务持续生成，浏览器保存草稿、任务 ID 与勾选结果，断开后可恢复。
- 已筛选的问题直接成为新录音的 AI 原文问透对象；无提纲保留七维题目。人工已问独立保存，不增加问透比例。历史、待办、续访、导入与项目位于录音首页的同页折叠区；无进行中记录时进入准备流程。
- 浏览器分片持久化、恢复上传与后端固定编号去重；转写失败可重试同一原片，时间点依据实际音频长度。实时追问后台生成，不阻塞转写上传。
- 手机熄屏/系统冻结网页不能由浏览器保证持续录音。鸿蒙 5/6 路线使用原生采音与后台录音长任务，保留网页界面和服务端；本轮经用户确认仅交付原生源码工程，HAP 编译、签名、真机验收与上架属于下一阶段。
- 项目创建人可选择 2–50 场已结束且有逐字稿的访谈，综合全部逐字稿与已有纪要生成一份持久化总访谈记录，支持 Word/Markdown 导出；无逐字稿时不可仅凭纪要参与。
- 项目支持一键 ZIP 下载当前可见的已结束资料，包含实际录音、完整 TXT/JSONL、已有 MD/DOCX、清单及缺项说明；无音频不伪造，未结束/导入中需先完成。默认 200 场、2 GiB 实际资料总量、1000 万字符、20 万段，超限不截断。逻辑存储不变，解压得到真实项目目录。ZIP 未加密；下载前复核权限与快照，之后撤权不能收回已传字节。
- 长稿逐段提取原文证据，跨访谈按主题综合，保留来源编号、段落与时间引用，区分共识、分歧、时间变化与数字口径。以逐字稿为事实依据，纪要作为辅助，补充遗漏细节；单次材料超过 200 万字明确拒绝，不截断原文。
- 总记录持久后台生成并显示阶段，执行进程中断后可按过期租约恢复，重试耗尽可人工重新提交；无新队列记录的旧中断任务明确提示重试。来源修改、删除、移出项目或权限撤销后禁止导出失效记录；删除访谈/逐字稿片段同时清除相关派生正文。
- 录音和转写前，采访者必须自行取得受访者知情同意。
- 音频分片仅用于转写，当前处理流程结束后清理临时原始文件和 WAV 文件。
- 会话、逐字稿、建议和报告保存于本地 SQLite 数据库。
- 音频、逐字稿或提示信息会发送给已配置的第三方模型服务，使用者需遵守相应数据合规要求。
- AI 提纲、追问、逐字稿和报告均可能存在错误，发布或决策前必须人工核验。
- 不得在日志、规范或前端中展示 API Key、令牌和其他敏感配置。

## 9. 非功能需求

### 9.1 性能

- 历史列表在普通本地数据量下应在 1 秒内展示。
- 会话详情首屏目标不超过 3 秒。
- 音频上传和转写不得被自动命名阻塞。
- SSE 建立后，服务端事件应尽快显示，具体延迟受网络和模型服务影响。

### 9.2 稳定性

- 页面刷新、SSE 断线和服务重启后，进行中会话仍可恢复。
- 音频上传失败最多自动尝试 3 次，并保留明确错误状态。
- 模型调用失败不得破坏已入库转写。
- 报告生成失败后允许从历史详情页重试。

### 9.3 兼容性与可用性

- 优先支持最新版桌面 Chrome 和 Edge。
- 正式录音依赖 `MediaRecorder` 与麦克风权限。
- 桌面宽屏显示左右采访插画；窄屏自动隐藏，不能影响功能操作。

## 10. 异常与边界场景

必须提供明确反馈并保证已保存数据不被破坏：

- 麦克风权限拒绝或设备不可用；
- 空音频、音频过大、FFmpeg 不可用或转换超时；
- DashScope 或 Kimi Key 缺失、额度不足、超时或返回异常；
- AI 提纲结构不合格、问题不足或重复；
- 网络中断、SSE 重连、分片上传失败；
- 页面刷新、浏览器关闭、服务重启；
- 多标签页同时打开同一会话；
- 用户改名与自动命名同时发生；
- 结束访谈时仍有分片处理；
- 报告重复生成；
- 删除进行中会话或文件清理失败；

## 11. 核心验收标准

### 11.1 实战访谈

- [ ] 可填写完整访前信息并生成、编辑采访提纲。
- [ ] 可创建会话、取得麦克风权限并开始/停止录音。
- [ ] 录音按 10 秒分片转写，逐字稿顺序正确且不重复。
- [ ] 信号命中后可出现追问建议，并可标记已问或忽略。
- [ ] 七维覆盖率随转写或人工标记更新。
- [ ] 返回开场或刷新页面后，可恢复进行中会话。
- [ ] 结束时等待剩余分片，并成功生成和下载 Markdown 纪要。
- [ ] 历史会话可查看、改名、继续、补生成纪要和删除。
- [ ] 可上传受支持的音频或文字稿，看到处理进度，并生成带来源标记的结构化纪要。
- [ ] 不支持、超限、空白或损坏文件得到明确错误；上传临时文件在成功或失败后均被清理。

### 11.2 数据正确性

- [ ] 服务重启后转写序号连续，历史内容无覆盖、无重复。
- [ ] 用户手动标题不被 AI 自动标题覆盖。
- [ ] 已存在纪要时重复结束不重复生成。
- [ ] 删除后关联数据库记录消失，文件清理结果可追踪。

## 12. 成功指标

当前阶段通过服务日志和内部使用事件观察：

- 会话创建数、完成数和完成率；
- AI 提纲生成成功率；
- 转写成功率和失败分片率；
- 追问建议使用率；
- 七维平均覆盖率；
- 进行中会话恢复成功率；
- 纪要生成成功率及平均耗时；

指标只用于判断产品可用性，不应收集与目标无关的个人信息。

## 13. 当前版本限制与后续方向

### 当前限制

- 单机 SQLite、单 API Worker 与独立任务进程；录音锁、命名和 SSE 仍在 API 进程内，整个系统尚不支持多实例部署；
- 认证模式下员工中心不可用时不得自动降级为匿名访问；登录会话及共享权限需要持续验证。免登录必须由操作者显式配置，仅适合本机单人使用；
- 七维覆盖模型主要针对商户调研，其他访谈对象的适配度有限；
- 转写按固定 10 秒时间段标记，不等同于精准说话时间戳；
- 录音按分片近似时间定位，不等同于精准词级时间戳；单次录音可在独立同意后进行云端说话人分离，但不建立可跨访谈识别真实身份的声纹库。

### 后续方向

1. 更细的团队项目空间与权限角色；
2. 不同访谈对象的专属覆盖模型；
3. 更精细的说话人身份识别与词级时间定位（须另行评估声纹安全）；
4. 标签与跨项目专题对比（项目内资料 ZIP 已纳入本轮）；
5. 多 Worker 下的共享事件总线、分布式锁和任务队列。

### 第一阶段任务可靠性验收

- 页面样式和主要操作路径不变，页面脚本拆分不改变原有录音行为。
- 新网页结束访谈获得后台任务响应，关闭页面后可查询进度和结果；旧同步客户端仍可调用。
- 模拟执行进程中断后，任务可在租约过期后重新领取；模型临时失败按有限次数重试，不无限计费。
- 重复请求、提交结果后进程中断再次领取，不重复生成业务报告或追加待办。
- 任务取消、访谈删除、来源改动、发言人同意撤回后，旧结果不得写回；取消不承诺撤回云端计费。
- 原有访谈、逐字稿、项目和原音保留。迁移仅新增执行状态及一次性音频回调凭据；旧内存导入须在切换前完成。
- 由管理员明确启动后台处理进程，不偷偷启停或上线。现网门禁和员工共享可见范围不变；统一 SSO、PostgreSQL/COS、完整引用数字程序核验和鸿蒙真机验收仍未实施。
