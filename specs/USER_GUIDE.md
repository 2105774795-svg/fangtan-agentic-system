## 1. 使用前须知

### 首页：汇言笔与时叙录

首页上下排列两个入口。上方“汇言笔”用于调研访谈，点击后使用原来的“实战访谈”和“现场录音”两个标签；下方“时叙录”用于私密人生讲述与书稿整理。两边的功能、原资料和权限不因入口调整而合并。原“人生之书”现在名为“时叙录”，无需重新建档或搬移已有讲述。本轮入口与名称调整须测试后上线，是否已更新以发布审计为准。

### 时叙录：独立私密空间

1. 在主页“时叙录”独立板块点“进入时叙录”，使用员工账号单独验证。桌面为左侧导航和右侧宽版内容，手机为单列。此处不继承访谈共享工作区的身份，其他员工不能查看你的档案；第一版不开家人分享。
2. 新建人物档案，填写称呼/简短介绍，确认已经取得讲述者的录音保存与云端处理同意。不同人物分档案保存，不要把未同意的家庭资料上传。
3. 开始讲故事，可点“播报问题”听设备本地中文音色，再点“录一段”；点“说完了”停止麦克风并提交。每段网页110秒自动收尾、服务器120秒/10MB上限；没有本地音色或录音权限时可以看问题、用文字讲述。第一版不是可随时打断的全双工电话。
4. 提交失败时当前页保留原片段及同一提交标识，点重试不会重复记稿。切后台停止采音，返回后检查并发送未提交片段；离开/刷新会清除当前设备未提交材料，先确认保存。已提交的故事仍在服务器。
5. 结束后可查看后台整理的人生线索与原话依据，不确定年代保留原话。人工确认只是认可该段回忆，不是独立事实核验。新一场可承接旧线索；本人可跳过、不谈或暂停。
6. 在“时叙录草稿”输入本次整理标题并生成。首版综合该人物全部已保存本人讲述，不按标题筛选年代/主题；每段列原话依据，可打开原讲述回听。核实后确认当前版本，再导出 Word/Markdown。追加原稿后旧版本过期，需要重新整理；原版本仍留存而不冒充最新稿。
7. 删除人物档案会删除本模块原稿、派生线索、章节并取消后台任务，文件清理失败会明确提示；退出或验证失效会清除当前页私密展示。已经下载的副本、备份及云服务已经处理过的内容不能靠网页删除追回。

界面继续保持原样，生成工作由独立后台进程执行。管理员须同时运行网页服务和 `worker.py`；只运行网页时，AI 提纲、导入、纪要、总记录、问透评估及发言人分析会排队等待。新任务进度保存在数据库，可在断开页面后继续查询；进程中断后按租约恢复并有限重试。本轮三项增强须完成测试和真实联调后再发布，本文不表示已经上线。

本轮流程：“现场录音”首页仅突出一个主录音键，其他管理与导入操作收在同页折叠区。点击录音键后再进入准备页，填写主题、对象、行业、城市和市场/园区；不再填写区县、街道/乡镇/村或具体地址，历史访谈中的原有地区信息仍保留。

AI 生成时先联网查询指定城市与具体市场/园区，在原背景卡片显示公开资料摘录、可点开的来源和检索时间，再显示问题。来源可能较旧，并不等于当前经营事实已独立核实；同名异地、无资料或检索失败会说明，仍可生成提纲。搜索只发送地点名称，不发送逐字稿或受访者资料。生成在服务器后台继续；返回页面可恢复结果，当前浏览器保存准备草稿和勾选状态。

编辑提纲后勾选需要的问题。在现场录音准备页，点“开始录音 · 已选 X 道问题”即创建会话并请求麦克风；不带提纲时可点“直接开始录音”。若从“实战访谈”的“带筛选提纲进入录音”进入，则先显示工作台，再点“录”采音。原摸排卡片按逐字稿评估所选问题是否充分回答，可点开看证据与下一句追问。手工“问过”另存、不增加问透比例；无提纲时使用原七维题目。

“历史会话”“全部待办”“继续最近访谈”“导入已有材料”与项目入口位于现场录音首页的折叠区。有未结束访谈时，“继续最近访谈”恢复该会话，再点“录”继续采音；没有时进入准备流程。重复的“继续最近一场未结束的访谈”入口已移除。

浏览器尽量保持屏幕常亮，分片在本机缓存后上传，返回前台或恢复网络后重试，固定编号避免重复录音。但浏览器无法保证熄屏、切后台或系统冻结后的持续采音，请保持前台录音；缓存保护只覆盖已产生的分片，不会补回麦克风被系统暂停的声音。

鸿蒙 5/6 原生方向使用系统采音和后台录音长任务。当前经用户确认仅交付 [`harmonyos`](../harmonyos/README.md) 源码，尚未安装包签名与真机验收；请不要把浏览器当前功能视作已安装原生 App。

“汇言笔”内部提供两种使用方式：

- **实战访谈**：准备主题、对象、行业和地点，生成、编辑并筛选采访提纲；
- **现场录音**：录音、实时转写、追问提醒、摸排进度和纪要生成，也可展开历史、待办、导入和项目管理。

使用实战录音前请注意：

1. 先取得受访者的录音和数据处理授权；
2. 确认电脑麦克风可用；
3. 保持浏览器和服务端网络畅通；
4. AI 转写、建议和纪要可能出错，正式使用前必须人工核实；
5. 使用与会议龙虾相同的员工账号登录；访谈默认仅本人可见，需要共享时在历史详情中明确添加同事。

现场录音结束后可在“历史会话”回听录音、点击逐字稿时间点定位、查看/勾选待办、向逐字稿提问、按项目分组并人工修订纪要。文字稿上传不保留原始文件；音频上传和实时录音会保留原件直至访谈被删除。

## 2. 首次安装和配置

### 2.1 准备 Python 环境

在项目根目录打开 PowerShell：

```powershell
Set-Location "C:\code\fangtan-agentic-system" # 改为你自己的克隆目录
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -i https://mirrors.aliyun.com/pypi/simple/ -r backend\requirements.txt
```

如果虚拟环境已经存在并可用，不需要重复创建和安装。

### 2.2 配置模型服务

首次运行时复制配置模板：

```powershell
Copy-Item -LiteralPath ".\backend\.env.example" -Destination ".\backend\.env"
```

编辑 `backend/.env`，至少填写：

```env
KIMI_API_KEY=你的Kimi密钥
DASHSCOPE_API_KEY=你的DashScope密钥
FANGTAN_PORT=18995
FANGTAN_PUBLIC_BASE=http://127.0.0.1:18995
```

- Kimi 用于生成提纲、追问、自动标题和纪要。
- DashScope 用于录音转写。
- 本地地址会使用 Base64 同步转写，不要求公网回调。
- 部署到公网 HTTPS 后，可将 `FANGTAN_PUBLIC_BASE` 改为实际公网地址。
- 不要把 `.env` 或 API Key 发给他人、写入文档或提交到 Git。

## 3. 启动、访问和停止

### 3.1 启动服务

从项目根目录执行：

```powershell
Set-Location ".\backend"
..\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 18995
```

看到以下提示表示启动成功：

```text
Uvicorn running on http://127.0.0.1:18995
```

浏览器打开：<http://127.0.0.1:18995/>

如果当前命令行已经位于 `backend` 目录，不要再次执行 `Set-Location .\backend`，直接执行第二行启动命令。

在第二个 PowerShell 窗口，从项目根目录显式启动后台进程：

```powershell
.\.venv\Scripts\python.exe backend\worker.py
```

已经位于 `backend` 时用 `..\.venv\Scripts\python.exe worker.py`。后台进程不监听网页端口，须与网页服务使用相同虚拟环境、配置及数据目录。生产启用步骤见 [`启动说明`](../启动说明.md)，不能通过“网页能打开”推断后台处理已运行。

### 3.2 停止服务

在正在运行服务的 PowerShell 窗口按：

```text
Ctrl + C
```

后台进程有独立窗口，需要停止时也在其窗口按 `Ctrl+C`。当前云端调用可能要到安全检查点才能退出，不能保证即时撤回或免计费；不要为停止一个进程而终止其他程序。

### 3.3 重启服务

先按 `Ctrl + C`，再重新执行启动命令。修改了后端路由或静态资源挂载后，需要重启服务，并在浏览器按 `Ctrl + F5` 强制刷新。

如果原终端已经关闭但端口仍被占用：

```powershell
$fangtanConn = Get-NetTCPConnection -LocalPort 18995 -State Listen
Stop-Process -Id $fangtanConn.OwningProcess
```

确认停止后再执行启动命令。若查询提示“找不到任何匹配对象”，说明端口已释放，不需要再次执行 `Stop-Process`。

## 4. 开始一场实战访谈

### 4.1 填写访前信息

打开“现场录音”后，点击主录音键进入准备页，再依次填写；也可从“实战访谈”进入相同的访前设置：

1. **当前员工**：登录后自动填写，用于内部使用量统计，不必手动输入；
2. **访谈主题**：建议填写，例如“社区便利店客流变化”；
3. **访谈对象**：选择最符合受访者身份的一项；
4. **所属行业**：选择对应行业，不确定时选择“综合/不限”；
5. **地区市场**：填写城市和市场/园区，例如“重庆市、双福国际农贸城”；
6. **采访重点/提示词**：可填关注方向，例如“房租、人工、外卖抽佣”；
7. **采访提纲**：一行一个问题，可手动填写或由 AI 生成。

### 4.2 生成和编辑采访提纲

1. 先填写“访谈主题”、城市及市场/园区；
2. 点击“AI 生成采访提纲”；
3. 等待系统生成，先阅读地点背景、来源、检索时间和待核实提示；留意来源日期及同名匹配是否准确，再查看问题；
4. 在文本框内检查、修改、删除或补充问题，并勾选本次要问的内容；
5. 现场录音准备页点击“开始录音 · 已选 X 道问题”，或在“实战访谈”点击“带筛选提纲进入录音”；仅已选问题成为录音摸排提示。地点背景不是受访者原话，不进入摸排问题列表。

如果再次点击生成，系统会提示现有内容将被覆盖。AI 生成失败时，可以继续手动填写，不影响开始访谈。

### 4.3 进入现场

点击页面顶部“现场录音”，先进入简洁首页。主录音键打开准备流程，确认地区、提纲与问题选择后再进入工作台；导入材料、历史、待办、续访和项目在同页折叠区中展开。仅打开首页或准备页不会产生空录音，也不会启动麦克风。

请先向受访者说明用途并取得录音同意。现场录音准备页下方的“开始录音 · 已选 X 道问题”或“直接开始录音”会创建新会话并请求麦克风；授权后开始采音。实战访谈中的“带筛选提纲进入录音”仅进入工作台，随后还需点“录”开始。新会话提供开场参考话术和录音授权提醒，不替代采访者事先取得同意。

## 5. 现场录音页面

### 5.1 开始和停止录音

- 现场录音准备页点击开始按钮后即可请求麦克风并采音；从“实战访谈”进入或恢复已有访谈时，点击工作台中央“录”开始；
- 浏览器首次使用时选择“允许使用麦克风”；
- 录音中按钮显示“停”，页面开始计时；
- 再次点击“停”暂停录音；
- 暂停后仍可再次点击“录”继续同一场访谈。

系统约每 10 秒上传一次录音分片。状态栏可能显示“录音中”“转写中”“上传失败，正在重试”等信息。

### 5.2 查看逐字稿

每个分片转写成功后，文字会按时间顺序出现在页面中。网络或模型服务较慢时，转写可能延迟出现。

如果出现错字，不会影响继续录音；当前版本暂不提供逐字稿在线编辑功能，正式引用前请在下载的材料中人工校对。

### 5.3 使用采访提纲

页面显示访前确认的提纲。点击条目可看 AI 判断、受访者原话、段落/时间和待追问内容。你仍可标记“问过”，标记会保存，但不表示已经问透，也不提高 AI 问透比例。

### 5.4 使用追问建议

当系统识别到值得深挖的表达时，会出现“追问建议”卡片：

- **已问**：采用了该建议；
- **忽略**：当前不使用；
- “为什么这么问”用于解释建议目的；
- “备选”提供另一种表达方式。

追问建议是辅助，不要求逐条照读。应根据现场关系、隐私边界和采访目标自行判断。

### 5.5 查看摸排进度

带入筛选提纲时，AI 根据完整逐字稿判断所选问题；没有提纲时，仍使用七个参考维度：

- 经营者画像；
- 经营现状；
- 成本结构；
- 竞争与位置；
- 政策与环境；
- 家庭与个人；
- 变化与预期。

原卡片显示“尚未讨论、仅被提到、仍需追问、已有充分回答”四种状态。点开可看真实原话依据和追问；百分比只统计充分回答，不因关键词出现或人工已问就加分。长稿分块增量分析，页面会说明排队、失败或新增内容待分析，旧结果不等于最新全文已分析。

AI 仍可能误判，尤其转写有错或回答含蓄时，应结合录音核实。旧资料不会因升级或打开列表被批量自动送云端；需要时点击“根据最新逐字稿重新分析”。

这套七维模型主要面向商户访谈；采访企业高管、专家等对象时，只作为参考，不应机械追求 100%。

### 5.6 临时离开但不结束

点击顶部“实战访谈”返回开场页时，系统会停止当前录音并保存已上传内容，但不会结束会话。

### 5.7 导入已有录音或文字稿

1. 按需在准备页设置主题、访谈对象、行业和采访重点；
2. 点击顶部“现场录音”，展开同页折叠区并选择“导入已有材料”；
3. 点击选择文件或把文件拖入上传区域；
4. 点击“分析并生成纪要”，等待进度完成；
5. 完成后系统自动打开纪要，并把逐字稿和纪要写入历史会话。

音频支持 MP3、M4A、WAV、AAC、OGG、FLAC、WMA、WEBM、MP4（最大 200MB）；文字稿支持 TXT、MD、DOCX、SRT、VTT、CSV、JSON、HTML（最大 20MB）。文字稿有效正文最多 50 万字符、1 万段，超过时请拆分或合并过短段落后上传。

纪要会整理基本信息、摘要、关键结论、行动项、主题章节、关键原话、数据、风险、待核实项和后续追问。音频使用时间戳定位，纯文字稿使用段落编号定位。模型不会可靠地替代人工校对，尤其应核对姓名、数字、责任人和截止时间。

音频处理中间切片会在该步骤结束后清理；原始上传副本在确认任务成功或取消后删除，失败时可能暂留用于恢复。音频归档原件保留供回听，文字稿成功解析后保留标准化逐字内容。分析期间返回上一页不取消任务，完成后从历史查看；已归档原文的重试只补纪要，不重复插入逐字稿。升级前旧内存导入任务须先完成，不能自动恢复未保存的旧进度。

之后可以通过：

- “继续最近访谈”；
- “历史会话”中的“继续访谈”；

重新进入现场。

## 6. 结束访谈并生成纪要

1. 确认访谈已完成；
2. 点击“结束访谈 · 生成纪要素材包”；
3. 系统自动停止录音并等待剩余分片上传、转写；
4. 等待 AI 生成纪要；
5. 在报告页查看内容；
6. 点击“下载 Markdown”保存文件。

结束后会话不能继续录音。如果仍有分片上传失败，系统会先重试；仍失败时会提示，不会假装已完整生成。

纪要是“素材包”，不是可直接发表的成稿。请重点核对：

- 人名、机构名、地点和日期；
- 金额、比例、数量和时间跨度；
- 因果关系与受访者原意；
- AI 标记的金句和待核实项。

## 7. 历史会话管理

### 7.1 打开历史记录

在首页点击“历史会话”。列表会显示：

- 会话标题；
- 进行中或已结束；
- 访谈对象与行业；
- 转写条数；
- 纪要状态；
- 创建时间。

### 7.2 查看会话详情

点击任意会话卡片进入详情页：

- 有纪要时默认查看纪要，可切换到逐字稿；
- 无纪要时查看逐字稿；
- 进行中的会话可点击“继续访谈”；
- 已结束但纪要未生成成功时，可点击“生成纪要”。

### 7.3 修改标题

在详情页顶部修改标题后点击“保存”。标题不能为空，最多 80 个字符。手动保存后，AI 不会再覆盖该标题。

### 7.4 下载纪要

纪要状态为已生成时，点击“下载纪要”保存 Markdown 文件，或点击“下载 Word（含逐字稿）”保存 DOCX。

### 7.5 项目文件夹与总访谈记录

1. 打开“现场录音”，展开同页折叠区中的“项目文件夹”，输入名称新建项目。项目可以暂时为空，进入项目后可修改名称。
2. 实时录音结束或已有材料分析完成后，在纪要页的“保存到项目文件夹”选择已有项目并保存，或填写新名称后点击“新建并归档”。逐字稿、纪要与录音会归入同一项目。选择“暂不归档”仍会保存访谈，只是不放进项目。
3. 已有访谈可在历史详情的“项目”中选择已有名称或输入新名称后保存；清空名称可移出项目。
4. 进入项目，勾选至少 2 场已结束且有逐字稿的访谈，填写总记录标题，点击“合并选中访谈”。单次最多 50 场；“全选”只针对当前已加载的可合并访谈，更多记录可继续加载。尚无单场纪要也可参与，缺少逐字稿的记录不可合并。
5. 生成可以后台继续。再次进入项目，在“已生成的总访谈记录”查看正文、来源访谈，并导出 Word 或 Markdown。生成失败时可重新选择来源访谈，再次提交。
6. 项目详情点击“下载项目资料包”，可一次取得按“项目/访谈”分目录的 ZIP：已留存录音、完整逐字稿 TXT/JSONL、已有纪要 MD/DOCX，以及清单和说明。纯文字稿没有音频、尚无纪要等会写明缺项，不会伪造或自动补写。Word 只含纪要，逐字稿单独完整提供。

资料包只含你当前可见的资料，项目若有可见的未结束/导入中访谈，请先完成后下载。单次默认最多 200 场、2 GiB 资料、1000 万字符和 20 万段，超限会明确要求拆分，不静默截断。ZIP 未加密，下载前会复核权限和资料版本，但已传出的内容无法因之后撤权而收回，请妥善保存、勿随意转发。应用内项目仍是逻辑归属，解压后你的电脑才出现真实目录；资料包不能替代整个数据目录备份。

总记录综合完整逐字稿和已有纪要，以原文核对事实并补充纪要遗漏的细节。长稿先逐段提取证据，再跨访谈整理主题、共识、分歧、时间变化、数据、待办和追问；来源编号如 `[访谈01·段落05·00:03:10]` 指向来源清单中的相应访谈，文字稿只标段落。AI 生成内容需结合原文核实，录音不会被拼接成一个音频文件。

来源逐字稿、纪要发生修改或访谈移出项目后，旧总记录停止导出，需重新生成；删除访谈或逐字稿片段时，相关总记录正文也会清除。单次材料超过 200 万字会提示减少选择，不会静默截断。应用内的项目文件夹不改变录音在磁盘上的原存储路径，备份时仍备份整个 `data/`。

员工认证模式下，只有项目创建人可改名和合并访谈。同事只会看到自己获分享的访谈，不会因为同名项目而获得整个文件夹的权限；总记录由创建人查看和导出。免登录模式仍以本机数据目录为单人工作区。

### 7.6 项目总览、共享与发言人分离

- 历史页的“项目总览”汇总当前员工自己创建或获分享的访谈、录音、纪要和未完成待办。详情页可填写项目名称。
- 详情页“团队共享”可添加指定在职同事，只授予查看权限。也可按纪要、逐字稿、Word 或录音单独生成 7 天有效的链接；链接持有者无需登录，创建人可随时撤销。生成后的完整链接仅显示一次，请自行妥善保存。
- 已结束且有录音的访谈可进入“区分发言人”。必须先单独取得所有发言人同意并勾选确认，才会把录音再次交给云端处理。结果仅标记本次录音的“发言人 A/B…”，不会自动辨认真实姓名，也不覆盖原逐字稿和纪要。
- 创建人可点击“删除分离结果与同意记录”；本地分离稿随即删除，原录音不受影响。已发送给云端的处理请求可能无法撤回。
- 重新分析期间或失败后若显示旧结果，页面会明确标注“上一次成功分析的结果”，不要误认为这是本轮输出。

### 7.6 删除会话

点击“删除会话”，认真阅读确认提示后确认删除。

删除会清理该会话的逐字稿、建议、报告和相关文件，无法通过页面恢复。删除进行中会话后也不能继续录音。

## 8. 常见问题排查

| 现象 | 原因 | 处理方式 |
|---|---|---|
| 页面打不开 | 服务未启动或端口不一致 | 确认终端出现 Uvicorn 启动成功提示，并访问 `127.0.0.1:18995` |
| `WinError 10048` | 18995 端口已被旧服务占用 | 停止旧进程后重新启动 |
| 查询端口提示找不到对象 | 旧服务已经停止 | 不再执行 `Stop-Process`，直接启动新服务 |
| 找不到 `backend\backend` | 已经位于 `backend` 又重复进入 | 保持当前位置，直接运行 `..\.venv\Scripts\python.exe ...` |
| `--port` 不是整数 | 两条命令粘贴到同一行 | 每条命令单独复制、单独回车执行 |
| 无法访问麦克风 | 浏览器权限被拒绝或设备不可用 | 在地址栏权限设置中允许麦克风，检查系统输入设备 |
| 提纲/纪要生成失败 | Kimi Key 缺失、网络或额度异常 | 检查 `.env`、网络和服务额度后重试 |
| 录音无转写 | DashScope Key、网络、音频设备或 FFmpeg 异常 | 检查终端错误、`.env` 和麦克风输入 |
| 页面仍是旧版本 | 浏览器缓存或服务未重启 | 重启服务并按 `Ctrl + F5` |
| 实时连接断开 | SSE 网络连接中断 | 保持页面打开等待自动重连，必要时从历史会话恢复 |
| 生成纪要一直等待 | 仍有音频分片上传/转写或模型响应慢 | 保持页面和服务运行，查看状态和终端日志 |

## 9. 数据位置与备份

默认运行数据位于项目根目录的 `data/`：

```text
data/
├─ fangtan.db        # SQLite 主数据库
├─ reports/          # 历史 Markdown 副本（新后台报告从数据库导出）
└─ uploads/          # 会话上传目录；临时音频处理后会清理
```

备份前建议先停止服务，再复制整个 `data/` 目录。不要只复制报告而遗漏数据库。

恢复时，应在服务停止状态下，用完整备份替换对应 `data/` 目录。执行覆盖前先保留当前数据副本，避免误删。

## 10. 安全与使用边界

- 未经受访者同意，不要录音或上传其发言。
- 不要在采访重点或提纲中输入不必要的身份证号、联系方式等敏感信息。
- 当前版本须连接员工中心；若员工中心不可用，系统会拒绝匿名访问。正式部署还应使用 HTTPS 并妥善备份数据库与留存录音。
- API Key 仅保存在 `backend/.env`，不得截图分享或提交 Git。
- AI 输出只能辅助采访和整理，不能替代记者核实、编辑审核或专业判断。
