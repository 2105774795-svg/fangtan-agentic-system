# 面试准备：实现与本机使用

本地实现于 2026-10-17。未提交、推送或部署 GitHub。

## 已实现的闭环

首页“面试准备” → 目标与真实材料 → 准备方案 → 逐题录音 → 追问 → 原音复盘 → 专项重练。

支持求职面试、论文答辩两个模板，中文或英文；辅导模式逐题反馈，模拟模式在结束前从服务端隐藏反馈。计划题数 2–12，默认按回答中的具体缺口智能决定是否追问、追问什么，不需要设置每题次数；作答原音总时长上限 3–90 分钟。时长限制在一次回答完成后检查，不截断正在录制的答案。

- 目标、材料和练习分别保存。材料支持修订与历史版本；每次练习冻结当时的材料、配置和问题计划。
- 支持粘贴、TXT、MD、DOCX、文本 PDF、PPTX；文件最多 20MB，单份正文最多 50000 字，项目正文合计最多 100000 字。PDF 最多 300 页，扫描件需先 OCR。PPTX 只提取文本框，不识别图像、图表或演示动作。
- 浏览器 MediaRecorder 每 10 秒 stop/start，形成独立可解码音频。复用现有 IndexedDB outbox、FFmpeg、转写与分片去重。
- 每次作答对应一个底层 session；服务端用途 interview_answer 隔离旧调研的七维分析、自动追问及纪要。旧会话入口不提供面试作答访问。
- “回答完成”核对全部 chunk_id 回执；尚未上传、转写失败、空语音不能进入下一题。已保存答案与下一题生成分离，模型失败可重试。
- 可暂停、恢复上传、刷新接续、放弃未提交回答后重录；浏览器关闭、系统后台限制或本机存储损坏仍不能保证零丢失。
- 复盘包含回答原句与改进建议。证据校验要求引文确实存在；音频定位按 ASR 分片范围，不承诺词级精度。引用存在不等于事实与语义已核验。
- 支持转写校对、原始识别稿保留、复盘过期提醒、Markdown 导出、专项重练和同题原文/原音并列对比。
- 不提供官方评分、通过概率或基于声音的人格判断；本版不提供专门的发音评分。

## 安装与启动

在 E:\fangtan-agentic-system 打开 PowerShell。此次已创建项目内 .venv 并安装后端、前端与测试依赖，生产前端也已构建。换机器时执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm ci
npm --prefix frontend ci
npm run build:platform
```

首次使用且 backend/.env 尚不存在时，复制 backend/.env.example 为 backend/.env，填写自己的 KIMI_API_KEY、DASHSCOPE_API_KEY。不要覆盖已有配置。密钥只由后端读取。

认证默认保持开启，使用已有员工中心账号，新增页面带登录入口。仅本机单人体验可显式设置 FANGTAN_AUTH_ENABLED=false，并只监听 127.0.0.1。本版没有另建面向公众的注册、支付或多租户管理系统。

两个终端分别执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --app-dir backend --host 127.0.0.1 --port 18995 --workers 1
```

```powershell
.\.venv\Scripts\python.exe backend\worker.py
```

打开 http://127.0.0.1:18995/，选择“面试准备”。API 与 Worker 使用同一配置和数据目录。不要增加 API workers。

如果调研长任务较多，可另外启动只处理面试任务的 Worker，降低等待：

```powershell
.\.venv\Scripts\python.exe backend\worker.py --interview-only
```

面试已按 [统一工作台整合说明](INTERVIEW_WORKSPACE_INTEGRATION.md) 接入原调研工作台：共用项目列表、顶部导航、流程画布、资料、任务和流式助手。原 `/?prep=<id>` 保留兼容并转到统一项目链接；逐题录音、转写确认、复盘证据和专业数据表继续复用，不与其他项目的资料混合。

面试对话输入框的加号菜单支持“上传简历附件”，也可将文件拖入输入区。支持 PDF、DOCX、TXT、MD、PPTX，单份最多 20MB，一次一份；旧 DOC 需另存为 DOCX，扫描 PDF 需先 OCR。上传后提取的正文以“简历”类型保存到当前项目资料，后续聊天使用该资料；这不会提交模拟面试的本题答案，也不会清空未发送文字。上传状态、解析错误与重试在输入框内显示，重试沿用请求编号避免重复保存；上传解析期间阻止离页。

## 数据和权限

新增 interview_preparations / materials / practices / turns / answers / reviews / requests 表，沿用同一个 SQLite 数据库；sessions 仅新增 purpose 列。所有新项目、材料、作答音频与 SSE 访问均校验实际所有者。

请求带 revision 和 request_id；重复请求返回当前快照而不重复创建。模型调用在事务外，结果提交检查任务租约、项目是否删除、当前任务身份和输入指纹。变更材料取消旧准备任务，已有练习仍保持自己的输入快照。

删除准备项目为逻辑删除：取消生成并阻断该模块访问，原始录音仍保存在本机数据目录；不表示物理擦除，也无法撤回已发送云端或已导出的副本。

## 试用反馈修复：材料删除、转写确认与引用失败

- 准备材料支持删除；删除会使准备方案过期并取消正在生成的旧方案。已开始的练习保留其材料快照，后续新练习需要重新生成方案。
- 每题点击“回答完成”后，先保存并展示转写及原音。可校对文字或重新录制，再点击“确认转写并继续”。确认前不会调用下一题模型；刷新后仍保留待确认状态。练习页始终展示已提交回答的原文和回听入口，模拟模式仍不提前展示评价。
- 试用中失败根因为 feedback_quote_not_in_answer，并非密钥错误。新增原话证据目录、排版空白对齐及最多一次模型纠正。仍无法核对时，不展示不可靠反馈或采用该追问，按已保存计划继续，避免卡住练习；不通过模糊改写伪造原话。
- 新增错误分类说明，避免把所有失败都误报为配置问题。保存材料期间锁定输入，防止快速连续填写被上次保存回调清空。

验证：后端全量 297 项通过（面试专项 24 项）；TypeScript/Vite 构建通过；浏览器材料删除、转写确认、录音跨分片、刷新/离线恢复、复盘重练和手机布局通过。真实 Kimi 使用合成资料验证准备、追问和复盘通过，追问返回 3 条可核对反馈。未重新发送用户既有个人材料或录音。修复仅在本地，未提交或推送 GitHub。


## 历史问题、公司岗位与最后反问

### 使用入口

1. 在“准备与材料”中填写目标公司、目标岗位、面试轮次/对方角色、公司背景、岗位要求和资料来源，保存准备目标。也可上传“公司背景”类型的资料。这里使用本人提供的信息，不自动联网核实，也不伪造企业事实。
2. 在“以前被问过的问题”输入真实面试题，可补充上次回答和当时背景。保存后点“分析这道题”，查看考查意图、回答结构、对旧回答的分析、可能追问和准备动作。
3. 点“重新录音回答这道题”即可专项重练，不要求先生成整套准备方案。旧回答只是准备背景，不会变成本次的语音回答。每个项目可保存30题，保存的问题也会优先纳入下次问题计划；超过计划题数的可分别专项练习。
4. 智能追问根据当前回答的遗漏、模糊处和论证缺口决定。回答充分则进入下一题，存在值得深入的缺口才追问，并展示“为什么继续问”。不会因为预设次数机械追问，相同问题也不会被反复追加。整场仍受作答时长和防循环保护约束。
5. 求职练习正常结束时，默认进入“你有什么想向我们了解的？”反问环节；也可点击“进入最后反问”提前切入。像其他题一样录音、核对文字后确认。点击“结束本轮练习”属于提前退出，可以不完成反问。论文答辩不加入这个求职专用环节。
6. 最后反问点评包括问得好的地方、可改进的地方、结合岗位还适合问的问题、为什么值得问及适合时机，并在整场复盘和Markdown导出中保留。不会冒充公司回答，薪酬福利等问题结合轮次和对方角色判断，不一概判差。

### 数据与兼容

新增 interview_question_bank；turns 增加 turn_kind / decision_reason，practices 增加 candidate_review。公司岗位和问题库随练习冻结；之后修改准备信息不会改变已有练习输入。删除问题不会删除已保存的录音回答。所有操作仍校验项目所有权、revision、幂等请求以及任务租约和输入指纹。

旧项目默认采用智能追问；保留固定追问字段仅用于旧接口兼容，不在界面要求用户填写。新历史题分析复用持久任务队列。准备资料变更会将问题分析标为需要复核，并取消过期准备任务。

# 对话式准备与复盘补题（本地更新）

准备入口改为逐步对话，不再展开场景、模式、语言、题数、时长、材料类型等配置表单。首页已经给出明确目标时继续询问背景；背景和文件均可跳过。求职场景单独询问是否练习最后反问，并允许填写自己的要求。题数、时长、语言、反馈模式沿用默认值；明确写出的数字分钟、题数、英语回答、每题反馈或结束后统一复盘等偏好会用于本轮配置，完整要求同时传给模型。其他复杂表达仍由模型结合目标理解，不保证全部转换为控制参数。

对话进度通过 config.preparation_step 保存到项目，刷新或更换浏览器后仍能继续。旧项目的材料、练习和复盘保留。上传和粘贴材料收进可选入口，自动命名，无需先选材料类型；材料仍支持修订和删除。没有材料时允许围绕目标生成计划，模型不得假装已阅读简历或编造公司情况。

历史面试问题从准备页移到面试结束后的复盘页，先询问是否补充；上次回答和背景默认折叠。保存后可以分析、逐题重答，也可直接“结合复盘与补充问题，再练一轮”。下一轮合并历史问题与复盘薄弱题，去重后优先问补充题，无需为此重新生成整套准备方案；原练习和原复盘仍保留。

验收：`npm run test:interview:advanced` 覆盖对话进度恢复、必要澄清、自填反问要求、默认配置及明确偏好、跳过背景、录音转写、智能追问、复盘补题与下一轮衔接、手机宽度；`npm run test:interview` 保留录音与材料回归。使用 `scripts/serve-interview-test.py` 启动的 19001 隔离服务，测试资料及模型、ASR均为合成，不发送用户资料到云端。
