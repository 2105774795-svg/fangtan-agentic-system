## 架构边界

### 时叙录私密业务域（第一版）

首页上下双入口只改变导航层次：上方“汇言笔”包含原“实战访谈／现场录音”工作区，下方“时叙录”进入私密口述史。原“人生之书”更名不改变 `memoir` 技术命名、API、Cookie、表或文件存储，也不把两域资料互通。本轮须测试后发布，部署结论以发布审计为准。

新增 `memoir` 业务域，沿用单 API＋独立 Worker，不启动第二套共享工作区。UI 使用原样式下的独立页面与脚本，录音不会送往旧 `/api/sessions`。认证使用员工中心校验后的独立 Cookie，不依赖全局 `AUTH_ENABLED`，不认旧 `LOCAL_USER`；每次读写均在服务端验证档案所有者。主站门禁保持不变，第一版不开放非员工家庭成员入口。

`memoir_*` 专用业务表与原业务表共用 SQLite 文件以便和 `tasks` 在同一事务检查执行租约，但所有领域查询独立；原音保存在 `data/memoir-private/recordings/`，不进入 `data/recordings`、旧项目 ZIP 或通用历史。此为接口、数据表及文件命名空间隔离，不是独立加密数据库或针对服务器管理员的隔离。通用 `/api/tasks` 对 `memoir_*` 一律隐藏，独立任务端点再次校验身份和档案归属。

实时回合短请求执行“保存本人原话 → 承接追问”，失败不丢已保存原文；耗时记忆提取和章节写作进入既有持久队列。章节和记忆提交前同事务核对租约、档案是否存在、所有权和原稿指纹，删除取消任务并清理派生内容。半双工播报只用本地中文声音，首版不保证所有手机具有该音色，也不宣称浏览器熄屏持续录音。

本轮为“模块化单体＋独立后台任务”第一阶段。本地代码与说明交付后，由管理员明确决定是否发布和启用进程；不自动启动、停止或部署服务。页面视觉和业务流程不变，未引入微服务、Redis、Celery、PostgreSQL 或对象存储。

地区提纲以 `outline_jobs` 持久后台任务运行，浏览器保存草稿/任务 ID 并轮询；短提示采用低推理强度。`place_research.py` 先通过现有同域 Moonshot `tools/search_pro` 检索，仅发送 `city/market`，以真实搜索结果摘录构建背景及 `sources/claims/research_status/retrieved_at`；然后生成问题。来源和可用发布日期随结果保存，旧日期、同名异地、空结果与失败明确提示，不以模型记忆或生成链接冒充检索。网页资料可追溯但不是独立事实核验，也不作为访谈逐字稿证据。新地区仅 `city/market`，历史字段只读保留。

录音首页只突出主录音键，点击后再进入地区、提纲与勾选问题的准备流程。历史/待办/继续最近访谈/导入/项目位于同页折叠区，去掉重复续访入口。实时追问在音频处理锁之外执行，分片原音与转写不再等待提示词生成。

浏览器录音使用本机 Blob 队列和服务端 `audio_receipts` 实现重试去重，按实际音频时长归档。屏幕唤醒锁只能缓解前台自动熄屏，不能把浏览器变成系统后台录音服务。鸿蒙 5/6 使用原生 AudioCapturer 与 audioRecording 长时任务，Web 组件复用页面并桥接录音控制；原生传输继续走现有登录门禁，当前工程为源码交付阶段，未签名及真机验证。

```text
浏览器
  ├─ REST：AI 提纲 / 会话 / 已有材料导入与进度 / 报告 / 音频分片
  └─ SSE：逐字稿、覆盖度、信号、建议、命名与报告事件
          │
          ▼
Nginx（原主站登录门禁保持不变）
          ↓
FastAPI（app.py + task_api.py，仍为单 Uvicorn Worker）
  ├─ 实时录音、分片处理锁、命名与 SSE
  ├─ 请求校验、权限及来源资料检查
  └─ 提交任务 → SQLite tasks（job_queue.py）
                       ↓ 领取／租约／心跳／重试
              独立 worker.py（不监听端口）
                       ↓
              task_handlers.py + services/materials.py
                       ├─ Kimi：提纲、纪要、综合
                       ├─ 百炼／FFmpeg：转写、发言人分析
                       └─ SQLite 与原有录音目录：校验后归档
```

网页结构与样式留在 `static/index.html`，交互脚本拆为 `static/assets/main.js` 与 `recording.js`。`job_queue.py` 管任务执行权，`worker.py` 管独立执行循环，`task_handlers.py` 管五类业务结果，`services/materials.py` 管一致快照内完整原文读取。`task_api.py` 映射公开状态而不暴露 payload/路径/租约；`audio_access.py` 使 API 与 worker 可共享一次性 ASR 回调令牌。

当前是单机、单 API 进程加独立任务进程：SQLite 保存业务与任务，实时录音线程锁仍只负责 API 进程内串行化。若未来部署多个 API worker 或多实例，仍须迁移会话锁、命名及 SSE 总线；持久任务跨进程并不等于整个服务已多实例安全。

员工身份来自与会议龙虾共用的 `AUTH_API_URL`，本站独立保存哈希化登录令牌并设置 HttpOnly Cookie。会话以 `owner_id` 为主权限，`session_shares` 只授予指定员工只读权；未归属的历史数据不向普通员工开放。历史全文搜索、项目分组、录音下载、SSE、报告、问答和待办均复用此权限边界。音频原件保存在 `data/recordings/{sid}`，删除会话时一并清理。

上段描述内置认证模式。现有生产部署则保持 `FANGTAN_AUTH_ENABLED=false`，由 Nginx 主站员工门禁保护共享工作区；本轮不改变其可见范围，不宣称已实现线上个人隔离或统一 SSO。

## 数据与状态

- `sessions.status`：`live` 可续录，`importing` 为固定 ID 的导入占位，`done` 已完成，`deleting` 清理中。删除先取消任务再标记，在事务中移除会话及关联行。导入占位不能另排空稿纪要；已有流水线继续处理。
- `sessions.subject_source`：`default` 允许 AI 命名；`auto` 为自动标题；`user` 永不被自动任务覆盖。
- `sessions.industry`、`sessions.focus`：保存访前行业和采访重点，与 `outline` 一起作为实时追问和会后报告的上下文。三个新增字段均在缺列时通过 `ALTER TABLE` 兼容迁移。
- `reports` 是否存在优先表达 `ready`；否则按持久 `tasks` 状态映射 `generating/failed/none`。`tasks` 内部状态为 `queued/running/retry/ready/failed/cancelled`，保留进度、尝试次数与错误；中断可在租约过期后重新领取。
- `utterances.seq` 以会话内 `MAX(seq)+1` 为持久事实，`CHUNK_SEQ` 只是热缓存；ASR 处理期间持有该会话锁，避免同进程重复分配。
- 自动命名尝试标记存入既有 `suggestions` 表的内部 `auto_naming` 类型，避免新增业务表；此类型不向前端建议流展示。每场最多两次（早期一次、结束补偿一次）。

## 关键流程

### 访前设置与 AI 提纲

```text
录音键 → 准备页：主题 + 对象 + 行业 + 城市/市场 + 采访重点
          → Moonshot Search Pro：公开地点来源 + 原文摘录（失败显式）
          → Kimi JSON 提纲（外部资料仅作不可信参考）
          → 清洗、去重、数量校验
          → 原背景卡片展示来源与检索时间，用户编辑并勾选问题
          → 创建会话并持久化 industry / focus / outline
```

网页使用持久后台提纲任务，断开请求不取消生成；旧同步端点保留兼容，模型生成失败返回 502。地点检索失败不阻止提纲生成，但背景必须明确未确认。搜索最多 2 次、每次最多 5 结果，限制时间与 512 KiB 响应，不直接抓取来源 URL；过滤危险协议、字面私网及伪造引用。创建后的行业、地区和重点继续参与追问建议及报告生成。

录音准备页的“开始录音 · 已选 X 道问题”或“直接开始录音”在建会话后请求麦克风。实战访谈的“带筛选提纲进入录音”保持原路径：创建会话、展示工作台，再由“录”按钮采音；不能将两种开始时机视为一致。

### 音频与恢复

1. 上传接口确认会话仍为 `live`，进入 sid 锁。
2. 首次或缓存落后时查询 SQLite 的 `MAX(seq)+1`，分配序号并写入分片。
3. ASR 成功后按序入库，推送转写事件，再执行维度/信号/建议处理。
4. 浏览器刷新或服务重启后，通过 `/state`（或会话详情）从数据库恢复转写、覆盖度、提纲及建议，再连接 SSE。

### 已有材料导入

```text
multipart 上传 → 扩展名/大小校验 → 临时目录＋固定会话占位＋持久任务
       ├─ 音频：FFmpeg 统一为 16kHz 单声道并分段 → DashScope ASR
       └─ 文稿：按 DOCX/字幕/CSV/JSON/HTML/纯文本解析
                         ↓
                标准化 utterances → 原文一次事务归档
                         ↓
              Kimi 分段提炼（长稿）→ 最终纪要 → 清理临时目录
```

导入任务及固定会话占位写入持久数据库，执行进程只更新已存在会话、不复活被删除的占位。原文归档后可直接重试纪要，不重复插入逐字稿；失败保留恢复所需原文件，确认成功或取消后才清理任务目录。公开接口继续返回阶段/进度/结果，不暴露临时文件路径。

### 自动命名

```text
逐字稿提交成功 → 记录命名尝试 → 后台线程调用 Kimi → 条件 UPDATE
                                              ├─ default + 默认标题：写入 auto 并推送 renamed
                                              └─ 用户已重命名：不更新，丢弃结果
```

调用模型与音频请求分离；模型异常记录日志并推送 `naming_failed`，不会回滚已保存逐字稿。

### 报告生成

`POST /finish` 先关闭录音并查缓存。新版网页带 `X-Background-Task: 1`，无报告时持久入队并返回 `202`，通过 `GET /api/sessions/{sid}/report-job` 查询；旧客户端保留同步等待兼容路径，并与 worker 共用原子保存和来源检查。导入未完成时优先展示并复用导入任务，不对空稿生成报告。报告、待办及完成状态一次事务提交，缓存命中不重复待办；数据库报告为最终依据，不依赖 `.md` 副本。会话结束后上传返回 409。

### 删除

先校验创建人权限并等待当前分片处理结束，再标记 `deleting`，事务删除会话、逐字稿、建议、报告、共享、待办和问答记录，最后清理上传临时目录、报告与留存录音。文件清理失败记错误日志并在响应中返回 `files_deleted: false` 和失败路径；重复删除返回 `404`。

### AI 原文问透评估

`coverage_ai.py` 经独立 Worker 执行 `coverage` 任务，完整逐字稿按约 7000 字符分块、问题分批，并缓存稳定片段的评估；追加录音只补新片段，旧片段修改使相应指纹失效，最后分层合并。发布时复核会话、设置、逐字稿版本及执行权；删除时同事务清除结果、缓存和证据。只读查看不会批量触发历史稿上云，已有材料由用户明确发起分析。

四状态为 `not_discussed/mentioned/partial/sufficient`，非空评估必须附真实 `seq` 和连续原话，程序校验原文包含关系；泛泛表态、回避或仅记者提问不能算充分。`ratio` 仅为 sufficient 数量占比，人工 `manual_asked` 单独保存、不加分；可展示增量旧前缀，但标记 `source_stale` 与已分析段数。AI 结论、转写和证据语义仍需记者核实。原 UI 只在已有卡片增加证据、追问与状态，不引入新工作台。

### 项目资料 ZIP

`project_bundle.py` 为 `GET /api/projects/{project_id}/bundle.zip` 读取权限内一致快照，生成安全净化名称的“项目/访谈”目录，包含留存录音、完整 TXT/JSONL、已有 MD/DOCX、清单和缺项说明。不移动服务器原音，不用项目名直接构造磁盘存储路径；缺音频或纪要不伪造。

存在当前可见但未结束/导入中的会话时拒绝打包。默认限制 200 场、2 GiB 实际资料写入总量、1000 万文字字符与 20 万逐字稿段，超限和磁盘不足明确失败、不截断；开始下载前再次复核权限、归属和资料版本。临时包以受限权限创建并在结束/断开后清理，ZIP 本身未加密，下载开始后无法撤回已传字节。逻辑项目归属不变，用户解压下载包可得到真实目录；项目包不替代整个 `data/` 的备份。

## API 合同

| 方法与路径 | 用途 | 关键行为 |
|---|---|---|
| `POST/GET /api/outlines/jobs[/{job_id}]` | 地点背景与采访提纲任务 | 城市与市场两项地区约束，结果持久化并可恢复；返回背景、核实提示和问题 |
| `POST /api/outlines/generate` | 同步生成兼容端点 | 校验对象、行业及地区；返回背景、核实提示和清洗去重后的问题数组 |
| `POST /api/sessions/` | 创建会话 | 保存主题、对象、行业、重点和最终提纲 |
| `GET /api/sessions/?limit=&offset=` | 历史列表 | 默认 100 条，`live` 优先，返回计数及报告状态 |
| `GET /api/sessions/{sid}` | 会话详情 | 元信息、最多 500 条逐字稿、建议、覆盖度 |
| `GET /api/sessions/{sid}/state` | 恢复校准 | 兼容现有接口，数据库状态为准 |
| `PATCH /api/sessions/{sid}` | 手动重命名 | 去首尾空格，1–80 字，锁定为 `user` |
| `DELETE /api/sessions/{sid}` | 删除会话 | DB 删除幂等；文件清理结果明确返回 |
| `POST /api/sessions/{sid}/audio` | 上传音频分片 | sid 级串行；DB 分配 seq；转码、ASR 和后处理 |
| `POST /api/imports/analyze` | 导入已有材料 | 接收文件并启动后台解析、转写和报告任务；返回 202 |
| `GET /api/imports/{job_id}` | 查询导入进度 | 返回阶段、进度、结果会话或错误信息 |
| `GET /api/sessions/{sid}/events` | SSE | 历史转写带稳定 seq 事件标识，实时事件带 event id |
| `POST /api/sessions/{sid}/finish` | 生成纪要 | 后台标记返回 202；旧同步接口保留；成功缓存复用 |
| `GET /api/sessions/{sid}/report-job` | 纪要进度 | 返回报告状态、任务 ID、阶段及进度 |
| `GET /api/tasks/{task_id}` | 通用任务状态 | 权限内返回状态与尝试次数，不暴露执行凭据 |
| `POST /api/suggestions/{id}/{action}` | 更新建议状态 | action 仅允许 asked 或 dismissed |

列表中 `subject` 保留数据库原值，`display_subject` 在默认标题时显示“未命名 · MM-DD HH:mm”。报告状态独立于会话状态。

## 项目文件夹与综合记录

`projects` 保存独立命名的项目；`sessions.project_id` 关联归档层级，`project_name` 保留历史筛选兼容。迁移不移动录音文件，不用用户名称构造文件路径，同名项目按创建人隔离。空项目持久保留。

项目创建人勾选访谈后，后台读取全部逐字稿与已有纪要。小材料直接综合，长材料分别逐段提取原文证据与纪要线索，再分层归纳；逐字稿是事实依据，纪要不可替代原文。所有来源材料都会进入处理链，超限明确拒绝；结果附访谈/段落/时间标记和来源清单。

`project_records` 持久化正文、来源 ID 及材料指纹，执行进度由 `tasks` 补充。进程中断后租约过期可重新领取。发布前以 SQLite 写事务复核执行权、取消状态、来源及项目归属，阻止删除后回写；读取/导出时再次复核权限和来源指纹，失效记录禁止导出。删除访谈或逐字稿片段同时清除相关派生正文。缺少队列记录的旧生成中任务提示重新提交，不猜测恢复。

## 运维与后续演进

- `python backend/worker.py` 必须显式启动，与 API 共用配置和数据目录；systemd 模板为 `deploy/systemd/fangtan-worker.service`。未启动时任务排队，不自动退回网页进程执行。
- 领取任务生成独立租约令牌，心跳续租；失败在有限次数内延迟重试。发布业务结果必须在同一写事务检查租约与取消。领域提交和队列完成是两步，需支持领域已成功但再次领取时幂等返回；不保证外部模型恰好调用一次。
- 取消为合作式，已发出的云请求不能即时撤回，可能仍计费；旧租约不能清理新执行者文件。成功或确认取消后执行有限目录清理，文件失败记录日志。
- 升级只增建 `tasks`、`audio_access_tokens` 及索引，保留旧业务记录；切换前等待旧内存导入完成、暂停旧任务并备份。
- `data/uploads` 为临时文件，`data/recordings` 为原音；SQLite 是报告正文依据，新后台流程不再创建报告文件副本，旧副本按删除流程清理。
- PostgreSQL、COS、完整引用/关键数字程序校验及鸿蒙真机验收仍是后续事项。需要多 API 实例前先迁移实时录音锁与 SSE，不能仅增加 Uvicorn Worker 数量。
