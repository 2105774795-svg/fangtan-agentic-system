# 整体化调研 Agent 平台重构方案（讨论稿）

日期：2026-10-16

## 已确认方向

- 基于现有项目开发新平台，允许重新设计产品入口、前端与业务组织方式。
- 市场调研、企业访谈、口述史都进入同一个新工作台，通过不同 Skill 执行。
- 第一阶段取消全部认证：不依赖员工中心，不保留口述史独立登录；后期统一接入账号与权限。
- 首页突出“今天您想调研什么？”与输入框；发送后进入左导航、中画布、右对话工作台。
- 通过选择卡片补齐需求，每个阶段生成可查看、编辑、下载的成果，并关联画布节点。
- 手机端接续录音的产品形态尚待确定，本方案暂推荐先做手机网页与录音文件导入。

## 产品定义

以项目为单位、由对话驱动、用流程画布组织过程和成果的调研工作台。Agent 负责识别意图、推荐场景 Skill、补齐信息、安排步骤、调用工具、保存成果与解释下一步。用户负责确定目标、选择方向、修改和确认关键成果。

第一版以预定义流程为基础，允许 Agent 根据上下文调整分支和提问；暂不建设任意拖线即可编程的通用 Agent 平台。

## 核心交互

### 首页

米白背景、深色文字、克制动效和充足留白，参考用户提供的 MiMo 页面截图。以自己的名称和视觉资产呈现。

中心区域：小行文案“今天您想调研什么？”、大输入框、发送按钮；下方放市场调研／企业访谈／口述史示例入口、最近项目与查看全部项目。示例入口用于填入意图，不要求用户先研究菜单。

发送后先持久化草稿项目和首条消息，进入有项目 ID 的工作台；入口输入框过渡到右侧对话区。界面过渡与模型请求分离，慢请求不阻塞工作台显示。失败可重试，不重复创建项目。

### 工作台

- 顶部：项目名、保存状态、当前阶段；导出等次要操作收进菜单。
- 左侧：项目概览、调研流程、资料、访谈记录；设置放底部。Skill 选择不单独占主菜单。
- 中央：默认流程画布，自动布局，突出当前阶段，可缩放、折叠与定位。
- 右侧：Agent 对话、结构化选择卡片、任务进度、下一步操作，可折叠。
- 点击节点或附件：中央切到成果预览／编辑，保留回到画布入口；避免增加常驻第四栏。
- 手机界面不照搬三栏，重点显示本场提纲、录音／上传和保存状态。

## 场景 Skill 与流程

| 场景 | 需要补齐的关键信息 | 典型流程 |
| --- | --- | --- |
| 市场调研 | 地区、调研目的、行业、对象、范围、输出要求 | 需求确认→背景研究→调研计划→分对象提纲→多场采集→交叉分析→报告 |
| 企业访谈 | 企业／行业、访谈目的、岗位、关注议题、时长 | 需求确认→企业背景→议题与提纲→访谈采集→纪要与证据→企业分析 |
| 口述史 | 人物、关系、年代、主题、叙述范围、输出形式 | 讲述目标→人生时间线→分主题提纲→多次讲述→线索整理→章节草稿→人工审阅 |

“锦州调研”只能可靠提取地点，不能直接断定市场调研或行业。展示推荐场景并让用户一键确认或改选。已明确给出的字段不重复询问；每轮只补齐当前步骤需要的信息。

选项由 Skill 定义基础枚举和交互类型，Agent 可以推荐排序或提供补充建议，后端验证字段。城市／行业支持检索选择；目标、对象和关注点适合单选／多选；名称、特殊要求保留自由输入；允许“暂不确定”，由 Agent 建议默认值并说明影响。

每个 Skill 至少包含：标识、版本、适用意图、输入字段、步骤与依赖、可用工具、成果类型、质量要求和人工确认点。运行实例固定 Skill 版本；修改模板不改变历史项目。

Skill 是可复用场景方法，Workflow 是项目中的具体执行路径，Tool 是检索、生成、转写等可调用能力。不能仅把提示词文件当成整个工作流实现。

## 画布与成果

主视图采用流程图，表达顺序、分支、依赖和状态；阶段内部可使用树状结构展开主题、对象与问题。第一版先完成一种清楚的流程视图，思维导图作为后续可切换视图。

节点展示名称、状态、简短摘要、附件数量和下一步。状态包括待开始、待补充、运行中、待确认、已完成、失败和已过期。展开可看到背景报告、来源、提纲、录音、逐字稿、纪要或章节。

业务状态由服务端保存；画布根据项目步骤与成果生成，布局坐标单独保存。拖动视觉节点不会自动改变执行顺序。

一项成果拥有稳定 ID 和版本，保存来源材料、生成任务、所属阶段、修改时间与确认状态。修改调研目标或提纲后，下游内容标记“需检查／已过期”，由用户选择重算，不静默覆盖已确认文件。导出时再生成 Markdown／Word／ZIP，不把数据库正文和多个文件副本当作彼此独立的事实来源。

项目支持多场访谈：每场采集拥有独立提纲、录音、逐字稿和纪要，最后进入项目综合。口述史以多次讲述和章节组织，不机械套用市场报告结构。

## Agent 执行与实时反馈

建议采用“模型建议下一步＋服务端验证并执行”的方式。模型解析意图、生成追问卡片、建议工具调用；服务端负责字段校验、步骤依赖、任务幂等和成果落库。

各阶段提供确认点但支持连续执行：需求确认后可连续生成背景和计划；提纲确认后进入采集；综合报告或章节作为草稿等待审阅。已有材料可直接导入采集阶段，准备步骤可以补做或跳过。

后台任务继续使用现有持久队列，新增项目运行和步骤状态。队列任务解决一次执行，流程运行解决跨任务、跨人工操作的进度恢复。

先落库事件再推送，事件带递增序号；断线后补取事件并读取最新快照，SSE 只负责传输。文本增量、阶段进度、选择卡片和成果就绪分别表示，不能用动画模拟实际运行状态，也不把聊天记录作为唯一执行依据。失败支持单步重试和取消；原录音、人工修改与既有成果不因生成失败丢失。

## 手机端衔接

电脑选择某一场访谈的“手机采集”，生成短时、单次配对二维码。手机扫码后在电脑确认配对，再获得仅限该场采集的凭证；二维码不携带整个项目的永久访问权限。即使暂不接账号认证，也需要这种设备级操作范围控制以防资料串场。

服务端维护统一 project_id、run_id 和 session_id，提纲确认版本固定到该场采集。手机只承担提纲查看、录音／上传和状态查看，电脑接收同一场采集事件并更新节点。第一版同场只允许一个录音端，电脑负责观察与编辑其他成果。

手机断网先保留本地录音片段及未上传清单，恢复后按分片 ID 去重上传。上传状态、转写状态、分析状态分别展示；只有已上传并确认的片段才能显示为云端已保存。结束录音后仍有未上传片段时不能提前宣称材料已完整归档。

推荐第一阶段提供 HTTPS 手机网页与系统录音文件上传兜底。电脑当前 127.0.0.1 地址不能直接作为手机扫码地址，联调需手机可达的 HTTPS 服务地址。网页录音要进行 iOS／Android、浏览器／微信内置浏览器、切后台／锁屏、断网恢复验证；网页安装为 PWA 也不能替代后台录音验收。

第二阶段再根据真实使用情况选择小程序或原生采集端。小程序不是换一个二维码链接即可完成，仍需独立采集实现、部署配置与真机验收。若长时间锁屏录音是硬性要求，应单独比较原生端和小程序实测结果。

## 技术结构

建议新增 React＋TypeScript＋Vite 前端，画布评估 React Flow。现有原生页面保留为迁移期间的兼容入口，逐场景接管，最终让新工作台成为默认入口。

后端保留 FastAPI、SQLite 和独立 Worker，先维持单 API worker。新增 platform／skills／workflows／artifacts／events／capture 等职责模块，通过服务适配器复用旧业务能力，避免新 Agent 直接依赖 app.py 路由内部函数。

现有能力对应：place_research→背景研究工具；outline_generation→提纲工具；录音和 ASR→采集工具；纪要、问答、coverage_ai→整理分析工具；project_records→跨场综合工具；memoir→口述史业务工具；word_export／project_bundle→成果导出工具。

建议数据对象：projects、workflow_runs、workflow_steps、messages、artifacts、artifact_versions、resource_links、run_events、capture_handoffs。复用既有 sessions 和 tasks，通过明确的关联引用接入。已有 projects 字段不足时采用有版本的增量迁移，不直接复制另一套含义相同的项目表。

账号暂不建设。服务层预留统一身份上下文接口，当前返回本地工作区身份，不调用员工中心、不生成登录门禁。新平台的三类场景均走这一模式，口述史的旧鉴权依赖需要显式重构，不能只修改全局开关。未来账号接入覆盖项目、附件、搜索、下载、事件与手机配对，存量工作区的归属届时明确迁移。

旧项目的迁移规则单独制定：备份后迁移项目和会话关联，保留原始录音路径与旧 ID；缺失的工作流步骤标记为历史导入，不能假装已经执行过背景研究。

## 实施顺序与验收

1. **统一工作台与平台骨架**：完成首页、三栏布局、三类 Skill、选择卡片、项目持久化、流程画布、成果预览和无登录访问。以可标识的演示数据验证交互，不能据此宣称真实 AI 链路完成。
2. **接通真实执行闭环**：接入需求解析、背景／时间线、提纲、现有录音和材料导入、纪要／章节与项目综合。三个场景各有一条真实可恢复流程；模型密钥缺失时明确显示未配置，演示与真实执行可区分。
3. **手机采集联动**：实现配对、同场接续、分片恢复、电脑状态同步与文件上传兜底，完成真实设备验收。
4. **上线前完善与认证接入**：统一账号和资源授权、存量数据归属迁移、设备凭证管理、备份恢复与访问边界验证，再决定是否面向多人开放。

第一阶段交付检查：输入需求能建项目并进入工作台；三类场景能确认和切换推荐 Skill；选项可修改并保存；节点能打开相应成果；刷新后恢复项目与进度；运行中和失败状态真实可见；三类场景均不调用旧认证服务。真实闭环阶段另检查单步重试不重复生成、修改输入使下游正确过期、多场材料正确综合且引用可定位。

暂不优先建设：通用拖拽流程编程、Skill 商店、多 Agent 群聊、多模型配置中心、微服务迁移和复杂知识图谱。先形成可用的调研闭环，再根据需求增加扩展能力。
