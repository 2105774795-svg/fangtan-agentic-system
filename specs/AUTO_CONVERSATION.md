# 连续语音对谈

用户确认录音和云端处理说明，点击一次「开始自动对谈」，即可连续进行多轮访谈：等待人声 → 记录讲述 → 停顿计时 → 保存末段和提交 → Agent 回应 → 本地播报 → 自动继续收音。用户主动暂停、明确的暂停口令、结束或设备不可用会中止接续。

## 模块职责

- `frontend/src/conversation/useAutoConversation.ts`：统一控制自动/暂停模式和轮转。处理中的录音不会丢弃下一次收音请求；异步任务通过代次检查，暂停后的迟到回复不能重新开麦。助手轮次按 ID 去重，暂停口令只消费一次。
- `useConversationAudio.ts`：会话级 MediaStream 和 AudioContext、独立可解码的录音分片、顺序上传和幂等提交。普通换轮只结束录音并暂停检测；真正暂停、结束或离开才释放设备。未检测到有效发言的静音片段不上传；内存保留最近约一秒的前导片段，降低跨分片时丢失开头的风险。
- `voiceDetector.ts`：本地 Silero v5 人声概率检测；模型、AudioWorklet、ONNX/WASM 随构建产物发布到 `/platform-assets/vad/`，开发模式也由 Vite 提供。检测不可用时回退自适应音量阈值，并展示提示。
- `useConversationSpeech.ts`：预加载本地中文音色、分句朗读、播放结束及错误事件、按句长计算的超时兜底。没有本地中文声音时展示文字并继续收音，不使用未知远程音色。
- `retry.ts`：网络错误、408、429 和 5xx 最多重试两次，保持原片段/轮次 ID；权限、业务校验错误不自动重试。超过次数后保留 IndexedDB 录音和待提交索引，可刷新恢复。
- `ConversationRoom.tsx`：状态和倒计时展示、暂停/结束/打断入口、设置保存与文字输入切换。

后端沿用原有 `/audio`、`/turns`、`/events` 与 Agent/记忆/书稿接口，不改变档案结构。

## 停顿规则

默认 5 秒，可选 3、5、8 秒，保存于本机，下一轮收音生效。检测到持续约 300 毫秒的人声后才启动停顿判断；计时期间再说话会重置计时，仍属于同一轮。停顿结束后有约 300 毫秒确认窗。录音存储分片不是对话轮次，长讲述跨多个文件仍只提交一次。

这些是初始参数，需要结合真人轻声、方言、环境噪声继续校准。停顿计时不包含转写、模型和播报准备时间。初版是自动交替说话，AI 播报期间不录制；「我来说」可以手动打断。流式 ASR、自动插话和锁屏后台录音不属于当前实现。

## 异常与保存

空转写保持自动模式并继续听。临时上传/提交故障有限重试，已经持久化的音频可在刷新后恢复。暂停不丢弃尚未提交的讲述；恢复可接着说或重试发送。文字输入明确暂停自动收音，发送后可点击「继续自动对谈」。设备权限撤回或断开时提示处理，避免循环申请权限。

阶段标记和耗时可在浏览器 Performance 面板查看，名称以 `conversation:` 开头，只包含阶段，不写入原话、音频或密钥。诊断测量数量有上限。

## 构建与验证

```powershell
npm --prefix frontend ci --registry=https://registry.npmmirror.com
npm run build:platform
npm run test:conversation:auto
```

测试路由提供构建产物和合成 API，不启动 HTTP 服务、不调用真实 AI、不读取用户访谈。Windows 缺少样本时使用系统语音合成生成测试 WAV；其他平台需要自行提供该合成人声文件。脚本使用本机 Edge，也可通过 `PLAYWRIGHT_BROWSER_CHANNEL` 指定浏览器通道。

覆盖一次开始连续十轮、麦克风复用、30 秒静音、停顿重置、跨分片、空转写、有限重试、播报事件丢失、主动打断、迟到回复、准备中暂停恢复、设备断开、3/5/8 秒配置、暂停口令恢复、刷新恢复录音，以及真实 WebAudio/AudioWorklet/Silero/WASM 对合成人声的推理。结果及桌面/手机截图位于 `data/qa/auto-conversation/`。

测试使用合成人声及合成 API，不等同于真人麦克风和真实中文 TTS 的实机验收。体验前刷新已有页面，在安静环境下连续讲述多轮，确认设备权限、中文音色和停顿设置适合本人。

只修改前端时，现有 API 静态挂载会读取新的构建文件，通常刷新页面即可体验，无需重启服务。
